# StillRelay 0.3.0 — evidence with a paper trail

[繁體中文](0.3.0.zh-TW.md)

StillRelay 0.3 keeps task records cumulative and makes the source behind each new fact visible. A successful worker finish is still a report, not independent acceptance.

## What changed

- Shorter updates no longer clear accumulated `verified_facts`, `failed_attempts`, `artifacts` or `backups`. Retractions retain the original entry and record who withdrew it, when and why. Current blockers and constraints remain editable.
- New `verified_facts` writes require an ID, statement, checking method and sources. The server checks source links and adds `reported_with_source` metadata; it does not certify the claim or perform the stated check.
- Existing fact strings read as `legacy_unverified`. Reads annotate old values without rewriting database rows or historical audit events.
- `artifacts` remain references, not proof or permission to open a file. Read `unverified_artifacts` alongside them. Optional `finish.artifact_checks` checks local file bytes against SHA-256 values inside administrator-configured `artifact_roots`. A failure rejects the finish and retains its lease. Each request is limited to 100 files and 64 MiB total. Checks record an observation; they do not keep an immutable copy, and the file may change later.
- Task `exit_code` remains a worker report. The bundled runner records the direct child's result from `subprocess.wait` as a local observation, not as remote attestation, proof that every child process stopped, or proof that the task is correct. Heartbeats mean contact, not progress. Dynamic acquisition of extra resources remains deferred.

## Upgrade

Version 0.3 changes the `verified_facts` write format. Update clients that submit fact strings before using this release. Move an unverified observation to `summary`, or send a source-backed fact object. CLI and MCP apply the same rule.

Package names, CLI commands, MCP tool names and client connection settings remain the same. This name and connection compatibility does not preserve the old fact payload. Before relying on artifact checks through MCP, call `shared_task_status` and require `evidence_contract_version=1` and `artifact_checks_enabled=true`.

Upgrade the GitHub-sourced tool using this pinned release:

```sh
uv tool install --reinstall 'git+https://github.com/ChengLeH/StillRelay@v0.3.0'
```

No database replacement, automatic database migration or private Host rollout is included. Existing rows and history remain in place; legacy fact strings are annotated when read. There is no automatic acceptance of old claims.

## Trust and limits

Artifact checks run in the local StillRelay process. They add no HTTP endpoint, hosted service or remote file-access path. Configured roots limit which paths the process checks; they do not change operating-system permissions or isolate other programs running as the same user. Actor names are collaboration labels within one user's trust boundary, not account authentication or a sandbox.

The evidence records a source and a check report; a controller must inspect the actual evidence before accepting work. Files remain mutable after a check. Cross-host use and network filesystems are outside the verified scope.
