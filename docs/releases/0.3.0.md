# StillRelay 0.3.0 — evidence with a paper trail

Candidate release notes; publishing this document does not create a GitHub Release.

A shorter client update can no longer erase accumulated facts, attempts, artifact references or backups. Explicit retractions keep the original and record why it was withdrawn. Current blockers and constraints remain editable.

New fact writes require an ID, statement, checking method and sources. The server checks same-task event references and matching artifact evidence, stamps the report and calls it `reported_with_source`. It does not certify the claim. Legacy fact strings read as `legacy_unverified`; old database rows and audit events are not rewritten on read.

Optional `finish.artifact_checks` compares actual local file bytes with expected SHA-256 digests, within administrator-configured `artifact_roots`. Failed checks reject the finish and retain its lease. Ordinary artifact strings remain unverified references; read `unverified_artifacts` too. Checks are bounded to 100 files / 64 MiB total and do not preserve immutable copies.

**Upgrade:** update clients that write string facts before using 0.3. Connection settings and six MCP tool names remain the same. Use `shared_task_status` to confirm evidence capabilities; an older adapter must not be assumed to enforce them. No private Host migration or production rollout is included. See [English evidence contract](../../references/evidence.md) and [繁體中文](../../references/evidence.zh-TW.md).

Exit-code trust is now explicit: task values are worker reports; the bundled runner labels its local direct-child observation separately. Heartbeats still mean contact, not progress. Dynamic acquisition of extra resources remains deferred to avoid partial-reservation waits. No additional heartbeat thread, AST checker or automatic worktree is introduced.

The 0.2 token benchmark remains historical; it was not rerun for this evidence format. macOS verification and packaging results are recorded by the implementation run; Linux/Windows CI must be checked before publishing a release.
