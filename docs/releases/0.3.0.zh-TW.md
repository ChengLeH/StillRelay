# StillRelay 0.3.0 — 看得出查過什麼的證據

[English](0.3.0.md)

StillRelay 0.3 讓任務紀錄持續累積，也讓每項新事實附上來源。工作者成功結束仍是回報；另一位控制者查核後才算驗收。

## 這次改了什麼

- 較短的更新不再清除累積的 `verified_facts`、`failed_attempts`、`artifacts` 或 `backups`。撤回紀錄會保留原項目，記下誰在何時、因何原因撤回；目前的阻礙與限制仍可更新。
- 新寫入的 `verified_facts` 必須包含 ID、主張、查核方式及來源。伺服器會確認來源連結並加入 `reported_with_source` 標記，但不替主張背書，也不會代為執行所述查核。
- 舊事實字串讀出時標為 `legacy_unverified`。讀取只補上標示，不重寫資料庫舊列或歷史稽核事件。
- `artifacts` 仍是參照位置，不代表檔案已驗證，也不代表程式有權開啟檔案。請一併讀取 `unverified_artifacts`。選用的 `finish.artifact_checks` 會在管理者設定的 `artifact_roots` 內，比對本機檔案內容與 SHA-256 摘要。檢查失敗會拒絕 finish 並保留租約；每次最多檢查 100 個檔案、合計 64 MiB。檢查只記錄當下觀察，不保存不可變副本，檔案之後仍可改變。
- 任務的 `exit_code` 仍是工作者回報。隨附 runner 以 `subprocess.wait` 讀取直接子程序的結果，並標示為本機觀察；這不是遠端證明、整棵程序樹都已停止的證明，也不能證明任務正確。心跳代表聯絡，不代表進度。動態增加資源仍暫緩。

## 升級

0.3 改變 `verified_facts` 寫入格式。原本送事實字串的用戶端必須先更新。未查核的觀察可放在 `summary`，或改送附來源的事實物件。CLI 與 MCP 套用相同規則。

套件名稱、命令、MCP 工具名稱及用戶端連線設定維持不變，但名稱與連線相容不代表舊事實格式仍可使用。透過 MCP 依賴產物檢查前，請呼叫 `shared_task_status`，確認 `evidence_contract_version=1` 且 `artifact_checks_enabled=true`。

從 GitHub 安裝並固定在此版本：

```sh
uv tool install --reinstall 'git+https://github.com/ChengLeH/StillRelay@v0.3.0'
```

這次不替換資料庫、不自動遷移資料庫，也不部署到私人 Host。既有資料列與歷史紀錄會保留；讀取舊事實字串時才加上分類，不會自動驗收舊主張。

## 信任範圍與限制

產物檢查由本機 StillRelay 程序執行，不會新增 HTTP 端點、託管服務或遠端讀檔路徑。設定的根目錄只限制程序檢查哪些路徑，不會增加作業系統權限，也不能隔離使用同一帳號的其他程序。actor 名稱只是在同一使用者信任範圍內辨識參與者，不提供帳號驗證或沙箱。

紀錄只保存來源與檢查結果；控制者仍需檢視實際證據再驗收。檔案在檢查後仍可變動。跨主機與網路檔案系統不在已驗證範圍內。
