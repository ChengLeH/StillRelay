# StillRelay 0.3.1 — reviews that survive handoffs

[繁體中文](0.3.1.zh-TW.md)

StillRelay 0.3.1 makes independent review durable across chats and agent handoffs. A completed worker result can be reviewed later without relying on one chat to remember who checked what.

## What changed

- New tasks persist the reviewer's ownership, executor and run binding, lease generation, checkpoints and result in task history.
- An interrupted review can resume only after the previous review execution is confirmed stopped. Resume rotates the review lease, so an older reviewer cannot write into the new review generation.
- Review results are tied to the current worker generation, completion revision and checked-output fingerprint. A changed or stale worker result cannot be accepted on the strength of an old review.
- New tasks require a separate reviewer before acceptance. After a passing result, the worker or another actor who is not the reviewer may accept it. Existing tasks retain their legacy acceptance path until `review_start` is used.

## Trust boundary

StillRelay records review ownership and results; it does not launch a sub-agent, authenticate the executor or prove that a host created an isolated review context. The host must start a fresh reviewer. A recorded pass is a review result, not proof that the work is correct. Heartbeats show contact, not progress or termination.

## Upgrade

This release adds review fields to the existing task records and history; it does not change the SQLite table layout or require a database migration. Keep using the existing configuration and state identity. Existing task data is not replaced.

Install this pinned release from GitHub:

```sh
uv tool install --reinstall 'git+https://github.com/ChengLeH/StillRelay@v0.3.1'
```

Package names, MCP tools and client connection settings remain the same. No private Host deployment is included. The project is distributed from GitHub, not PyPI.
