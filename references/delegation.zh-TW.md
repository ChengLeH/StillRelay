# 用 StillRelay 靜默委派

[English](delegation.md) | [繁體中文](delegation.zh-TW.md)

靜默委派把詳細執行過程留在工作者那邊。派工者仍然隔一段時間讀共同狀態、抽查證據，需要時介入；不是等全部結束才看。

## 角色跟著任務走

A 可以把任務 1 交給 B，同時執行 B 派來的任務 2；A 也可以另外把任務 3 交給 C。每份任務各有自己的控制者、工作者與執行編號。

三個角色只是範例。六個、七個或更多 agent 沿用同一協定；執行池容量是另一個設定，不是參與人數。本版仍屬同一主機、同一使用者信任範圍的合作工具。

狀態 MCP 不會替你選模型、聯絡任意 agent、喚醒休眠對話或增加執行權限。它儲存與查詢工作；實際執行由你原本已有的工具負責。

## 一份進度，三個職責

1. 控制者建立任務，儲存目標、限制、修改範圍與驗收條件。
2. 工作者或接合層接單、綁定確切執行編號，執行時把詳細日誌留在本機，重要進展寫回共同任務。
3. 控制者間隔讀取精簡快照，查證必要證據，最後由不同於工作者的控制者驗收。

[選用的靜默委派 Skill](../skills/silent-delegation/SKILL.md) 教 agent 執行這個流程。透過用戶端實際支援的方式安裝整個 Skill 資料夾；它需要已安裝的 CLI 或已連線的 MCP。MCP 連上不代表用戶端會自動讀取 repo 裡的 Skill。

## 通用命令接合層

使用現有的公開版設定；只有全新環境才初始化。所有參與者加入同一份設定與狀態 UUID。Mac 私有 Host 的舊格式不是自動遷移目標。

透過 `shared_task_apply` 或既有 CLI 請求協定建立任務：

```json
{"schema_version":1,"request_id":"create-check-001","actor":"agent-a","op":"create","task_id":"check-001","execution_pool":"local","resources":[{"kind":"path","path":"/absolute/project","mode":"write"}],"fields":{"title":"檢查專案","goal":"執行已授權的測試並保存證據"}}
```

再由已授權的執行器啟動：

```sh
shared-task-state-mcp --config /absolute/shared/config.json run \
  --task-id check-001 --actor agent-b --executor local-command \
  --cwd /absolute/project -- python -m unittest discover -s tests
```

接合層本身以前景方式執行，由原有工作執行器負責背景啟動、停止與續接。它在子程式啟動前接單並綁定身分，將詳細輸出留在本機執行目錄，送心跳、記錄實際結束結果，不會自動驗收。它使用明確的命令引數，不透過 shell 解析命令字串。

包裝的命令必須以前景方式維持自己的生命週期；會另外派出背景工作的命令，需要能追蹤那些工作的專用接合層。若停止結果不明，保留資源佔用供調查。啟動前已確認沒有任何子程式開始，才可釋放自己尚未使用的接單佔用。

本機日誌位於 `<data-root>/runs/<task-id>/<run-id>/`，任務的 `delegation.report_ref` 指向該目錄，重新連線後也能找回。命令正常記錄完成時，CLI 回傳子程序結束碼（0–255）；生命週期結果不明時回傳非零。原始日誌不經隱私過濾、不上傳共用狀態。POSIX 目錄／檔案權限為 `0700`／`0600`；Windows 請保持資料目錄 ACL 私密。

原接單程式已管理租約時，不要再接單一次。讓既有接合層沿用那份租約，統一負責心跳與結束更新。

## 間隔監督

```sh
shared-task-state-mcp --config /absolute/shared/config.json supervise \
  --task-id check-001 --after-seq 0
```

MCP 使用 `shared_task_supervise`，提供任務 ID 與上次回傳的事件遊標。每次呼叫讀取一份一致的資料庫快照；回傳筆數限制不是 agent 人數上限。查詢不送心跳、不改狀態、不自動讀取日誌參照，也不驗收任務。

監督時分開判斷：

- **聯絡是否正常**：心跳新鮮不代表工作有進展；過期也不代表原程式已停止。
- **是否有回報進展**：確認步驟、摘要與證據有沒有更新，不能只看版本號。
- **結果是否正確**：抽查必要的原始碼、產出與測試，才能形成驗收判斷。

依工作量選擇檢查間隔，健康時逐漸拉長；發現失敗、停滯或證據衝突，再讀必要的詳細內容。每組固定監督的任務各自保存遊標，新增任務先從零開始；不要拿另一組任務的遊標跳過尚未看過的更新。最後回報的進展附有世代編號；前一輪留下的證據，不算新一輪的進展。看過變更不等於已驗證變更。

## 人數與容量分開設定

參與人數沒有固定三人的設定。既有 `pool_limits` 控制同時佔用的執行容量。例如硬體足夠、管理者明確選擇時，可設定 `{"local":7,"cloud":null}`。本工具不會自行調高正式環境的容量；一個模型可能適合的執行名額，仍少於參與協作的 agent 數量。

重疊修改目標維持互斥。不同目標精確申報後並行；需要同時改同一份原始碼時，用獨立 Git worktree 與最後的依序合併。任務快照不負責合併程式。

## 接回既有 Mac MCP 流程

保留原有 Tunnel、Betterleaks、Headroom 與已授權執行器。把共同任務 ID 對應到既有工作串、世代與執行編號，由一個接合層負責租約生命週期。原生狀態與檢查點仍是執行器的證據，避免另外維護一套共同進度敘述。

若執行器有重新判定存活狀態的查詢／接回／結果入口，優先使用；不能只看原始檔中的 `running`。啟用 Skill 不需要替換正式資料庫、增加模型並行或重啟控制通道。公開套件不包含私有 Host 設定；隔離測試成功，也不等於正式用戶端已完成部署驗證。

## 可直接給 agent 的設定要求

> 請依 ChengLeH/StillRelay 的 MCP 指南安裝 StillRelay，加入現有共用設定，不另建狀態。如果本用戶端支援 Skill，載入選用的 silent-delegation Skill。使用我已授權的執行器做背景工作，詳細日誌留在執行端，間隔讀取共同進度與查證必要證據。不要更改模型並行數或權限。回報實際驗證過的連線與執行能力。

## 升級與回滾

StillRelay 是展示名稱，原有 `shared-task-state-mcp`、`shared-task-state` 命令與連線名稱保留。固定 Git commit 安裝，升級後重新載入用戶端連線；回滾時重新安裝原本固定的版本。本次只新增可選執行關聯，不遷移私有 Host 狀態、不重做歷史儲存。保留備份與歷史，不能拿舊資料庫覆蓋後來已驗收的工作。

命令工作者與 MCP 用戶端能驗證協定、角色互換與快照；它們不能證明休眠 agent 會自動醒來、模型一定遵循 Skill，或每個平臺介面都已驗證。Token 實驗也必須區分監督者看到的工具內容與全部模型用量／費用。
